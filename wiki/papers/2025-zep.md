# Zep: A Temporal Knowledge Graph Architecture for Agent Memory

Preston Rasmussen et al. (Zep AI) · arXiv, Jan 2025 · [arXiv 2501.13956](https://arxiv.org/abs/2501.13956) · Read: full paper

**Topics:** [How memory is organized](../topics/memory-structures.md) · [Updating and forgetting](../topics/updating-and-forgetting.md) · [Evaluating memory](../topics/evaluating-memory.md) · [Memory vs. long context](../topics/memory-vs-long-context.md)

Zep keeps agent memory in a knowledge graph where every fact records when it was true and when the system learned it, so a new fact can retire an old one without deleting it. On LongMemEval it beats putting the full history in context, with about 90% lower latency. All authors work at Zep AI, which sells Zep.

## Problem

By the paper's account, retrieval frameworks for agents mostly fetch from static documents, while enterprise agents need memory built from ongoing conversations and business data that change over time.

## Method

* **Three subgraphs:** episodes (raw messages, text, or JSON); semantic entities and the facts between them, stored as edges; and communities, clusters of connected entities with summaries, found by label propagation.
* **Bi-temporal facts:** each edge carries t_valid and t_invalid (when the fact held in the world) and t'_created and t'_expired (when the system recorded and retired it).
* **Ingestion:** entities are extracted from the current message plus the last 4 messages, then matched against existing entities with embedding and full-text search; an LLM decides which are duplicates. Facts are extracted between entities and deduplicated against edges between the same pair.
* **Updates:** an LLM compares each new fact with semantically related existing facts. If they contradict and overlap in time, the old fact's t_invalid is set to the new fact's t_valid. The old fact stays in the graph.
* **Retrieval:** cosine, BM25, and breadth-first graph search, then rerankers (RRF, MMR, episode mentions, node distance, or a cross-encoder). Results come back as facts with their valid and invalid dates, plus entity and community summaries.

## Results

* **DMR** (gpt-4-turbo): Zep 94.8%, against MemGPT's reported 93.4% and full conversation at 94.4%. With gpt-4o-mini, Zep 98.2% against full conversation at 98.0%.
* **LongMemEval_S** (about 115K tokens): 71.2% against 60.2% for full context with gpt-4o, and 63.8% against 55.4% with gpt-4o-mini. Context drops from 115K tokens to about 1.6K, and latency from 28.9 s to 2.58 s (gpt-4o).
* **By question type** (gpt-4o): the largest gains are on single-session-preference (20.0% to 56.7%) and temporal reasoning (45.1% to 62.4%). Knowledge-update goes from 78.2% to 83.3%. Zep does worse on single-session-assistant (94.6% to 80.4%). With gpt-4o-mini, knowledge-update goes down slightly, from 76.9% to 74.4%.

## Limits

* The authors note the drop on single-session-assistant questions needs more work, and that no benchmark yet tests memory over business data, or cost and latency at production scale.
* On LongMemEval, Zep is compared only with full context, not with other memory systems. The paper comes from the company behind the product.

## For my work

The closest design to my question: facts are retired with a valid-time instead of deleted, so the system can still answer what used to be true. But the evidence that this fixes updates is thin: knowledge-update results are mixed across the two models, and the paper doesn't measure how often the LLM misjudges a contradiction.
