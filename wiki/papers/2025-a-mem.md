# A-MEM: Agentic Memory for LLM Agents

Wujiang Xu et al. (Rutgers University, AIOS Foundation, independent researcher) · NeurIPS 2025 · [arXiv 2502.12110](https://arxiv.org/abs/2502.12110) · Read: full paper

**Topics:** [How memory is organized](../topics/memory-structures.md) · [Updating and forgetting](../topics/updating-and-forgetting.md) · [Evaluating memory](../topics/evaluating-memory.md)

Memory organized like a Zettelkasten: each interaction becomes a note with LLM-written keywords, tags, and context; the LLM links it to related notes and rewrites those notes' descriptions. On LoCoMo it beats MemGPT and other baselines in most categories while reading far fewer tokens.

## Problem

Existing memory systems store and organize memories in structures that developers fix in advance. The paper argues that such predefined schemas limit how memory can adapt as knowledge grows.

## Method

* **Notes:** each note has the content, a timestamp, LLM-generated keywords, tags, and a contextual description, an embedding of all of these, and links to other notes.
* **Link generation:** retrieve the top-k most similar notes by embedding; the LLM decides which ones to link.
* **Memory evolution:** for those neighbors, the LLM decides whether to update their context, keywords, and tags in light of the new note. The updated note replaces the old one.
* **Retrieval:** top-k by cosine similarity, mostly k = 10, with all-minilm-l6-v2 embeddings.

## Results

* **LoCoMo, GPT-4o-mini, F1** (column names as A-MEM labels them): A-MEM is best in four of five categories. The widest margin is Temporal, 45.85 against 25.52 for MemGPT. It loses Adversarial to the LoCoMo baseline (50.03 vs 69.23).
* **Tokens:** A-MEM's token length is 2,520 against about 16,900 for the LoCoMo and MemGPT baselines (GPT-4o-mini). A memory operation takes about 1,200 tokens and costs under $0.0003.
* **Ablation** (GPT-4o-mini, Multi Hop F1): 27.02 for the full system, 21.35 without memory evolution, and 9.65 without link generation and evolution.
* Also tested on DialSim and with six backbones, including Qwen2.5 and Llama 3.2 models.

## Limits

* The authors note that the quality of the organization depends on the LLM, and that the system handles text only.
* Evolution rewrites how old notes are described and linked. My inference: when a new note contradicts an old one, both stay, and nothing marks the old one as outdated.

## Ideas worth reusing

* **Links the LLM chooses:** Retrieve similar notes by embedding, then let the LLM decide which ones to link to the new note.
* **Memory evolution:** When a new note arrives, let the LLM rewrite related notes' context, keywords, and tags.

## For my work

Evolution is a soft kind of update: it changes an old note's context and tags, not whether the note still holds. A-MEM doesn't report on LongMemEval's knowledge-update questions, which would show whether that's enough.
